#### 3. 独热编码（One-Hot Encoding）深度理解
- **核心逻辑**：扫描整表 → 找出唯一值 → 拆列生成（出现为1，未出现为0）→ 删掉原列。
- **`dummy_na` 参数的作用**：
  - `dummy_na=True`：把缺失值（NaN）本身也当成一种特征类别，单独开一列。
  - `dummy_na=False`：把 NaN 当空气，缺失的行在新列里全为0。
- **学术总结**：适用于“无序的定性特征（Nominal Categorical）”、“离散型特征（Discrete）”、“输入特征（Input Features）”。
- **白话总结**：无序的，同级的，是特征。

## Day5（2026.10.5-2026.10.9）线性代数
### 概念理解
- **标量**：函数中的确定值
- **向量**：
1.标量值组成的列表，这些标量值被称为向量的元素，或分量。
2.可以根据数据库中的表类推，表的“一行”是一个“样本向量”，“一列”是一个“特征向量”。 向量里的每一个分量，就是数据库里最基础的数据单元。
3.人们通过一维张量表示向量。一般来说，张量可以具有任意长度，取决于机器的内存限制
- **长度，维度和形状**
  - **长度**：向量的长度通常称为向量的维度。
  Python的内置len()函数来[访问张量的长度]。
  返回该张量第0维的元素数量，也就是只关心有多少行
  当用张量表示一个向量（只有一个轴）时，我们也可以通过.shape属性访问向量的长度。
  - **维度**：张量维度=轴的数量，某个向量或轴的长度=轴上元素的数量
- **矩阵**：将向量从一阶推广到二阶。
  - 表示：
  - 转置：交换行和列
- **张量**：是描述具有任意数量轴的n维数组的通用方法。
  - 张量计算的基本性质：
  1.一元运算（只对一个张量做操作，比如求绝对值，求平方，求指数）不改变形状。给定具有相同形状的任意两个张量，任何按元素二元运算结果都将是相同的形状和张量。
  2.加和乘都不会改变张量的形状。
- **降维**：
  - 调用求和函数会沿所有的轴降低张量的维度，使它变为一个标量。
  **白话**把某一个方向的数全部加起来，然后把那个方向消灭掉
  sum可以求任意形状张量的元素和

## Day6 线性回归的从零开始实现——生成数据集（10.9-10.13）
### 概念理解：
- **回归**：经常表示输入和输出之间的关系。
- **线性模型**：y=kx+b，k为权重，b为截距，偏置。
**对于一个给定的数据集，我们需要找到其权重和偏置，使得根据模型做出的预测大体符合数据里的的真实值**
- **损失函数**：能够量化目标的实际值与预测值之间的差距，完美预测时的损失为0。为了度量模型在整个数据集上的质量，我们需计算在训练集n个样本上的损失均值（也等价于求和）。
- **解析解**：线性回归的解刚好可以用一个公式简单的表示出来，这类解就叫做解析解。
- **梯度下降**：可以优化所有深度学习模型。不断在损失函数递减的方向上更新参数来降低误差。
- **矢量化加速**：同时处理整个小批量的样本。对计算进行矢量化，从而利用线性代数库，而不是python的for循环，从而带来数量级的加速。

### 研究代码核心问题
- 1. **为什么在深度学习中线性回归的权重与偏置要为小数**
  - **学术**：深度学习采用梯度下降算法，每次训练执行：
           `新权重=旧权重-学习率*梯度`
  参数更新涉及极小步长（学习率 × 梯度），整数类型无法表示小数部分，会导致参数不更新，若权重为小数则会导致权重慢慢逼近为完美；且 PyTorch 的 matmul 要求操作数类型严格一致。
  - **白话**：调水龙头需要微调0.001圈，用整数只能拧1圈或0圈，模型完全没法收敛。
  - **代码**：`true_w = torch.tensor([2, -3.4])` 带小数点，torch.matmul 才不会报 expected scalar type Float but found Long。
- 2. **为什么有yield这个关键字就没有return，yield的作用是什么？**
  - **学术**：包含 `yield` 的函数即生成器函数，返回生成器对象（迭代器）。它实现惰性求值（Lazy Evaluation），每次调用 `next()` 才执行一次循环体并暂存状态，避免全量数据载入内存。
  - **白话**：`return` 是一锤子买卖，执行完函数就死；`yield` 是挤牙膏，挤一下停一下，等下一次循环再继续挤。
  - **结合代码**：`data_iter` 里用 `yield` 配合 `for` 循环，每次只交出10条数据。
- 3. **为什么抽取数据的时候是随机抽取呢，不会导致找不到关系吗？**
  - **学术**：小批量随机梯度下降（Mini-batch SGD）的核心机制。随机采样能消除样本顺序带来的梯度偏差，防止模型因连续看到同质化样本而产生梯度震荡。
  - **大白话**：
  1.打乱 vs 不打乱：不打乱时，如果前100条全是男生，后100条全是女生，模型参数的调整会从一个极端（偏高）滑向另一个极端（偏低），很难收敛。随机抽样能保证每次微调的“方向”都是整个班级的客观缩影。
  2.分批 vs 全量：全量计算可以算出完美的梯度，但一次性塞入1000条数据，显卡显存瞬间爆炸（这正是“算力消耗巨大”的真实原因）。分批读取配合随机打乱，才能兼顾“方向正确”与“内存友好”。
  - **结合代码**：`random.shuffle(indices)` 打乱的是“读取顺序”，但 `features` 和 `labels` 通过共享相同的 `batch_indices`，保证了特征与标签的绝对对齐绑定。 
- 4. **函数len（）到底是怎么数元素数量的**
  - **学术**：`len(tensor)` 返回张量第0维（dim=0，即行轴）的长度。
  - **大白话**：只数行，不数列
  - **结合代码**：如果 features 形状是 `(1000, 2)`，`len(features)` 返回 1000；如果形状是 `(50, 100)`，`len()` 也只返回 50。
- 5. **`yield features[batch_indices],labels[batch_indices]`这串代码什么意思。**
  - **学术**：在生成器函数中，利用高级索引（Advanced Indexing）进行批量采样。yield 挂起函数执行并返回一个元组 (X, y)；features[batch_indices] 和 labels[batch_indices] 则利用同一个索引张量，沿第0维（行轴）同步提取对应的数据行，保证特征与标签的绝对对齐。提取后的特征形状从 (1000, 2) 变为 (10, 2)，标签从 (1000, 1) 变为 (10, 1)。
  - **白话**：拿着洗好的 10 个号码牌（batch_indices），分别去特征仓库和标签仓库里，抽出编号对应的 10 行货物，用一根皮筋把它们绑在一起（元组），然后按下暂停键（yield），等下一次循环再继续抽。
  - **结合代码**：batch_indices 包含 10 个随机数（如 [898, 246, ...]）。features[batch_indices] 会精准抽取这 10 行，列数保持不变（依然是 2 列，代表 2 个特征）；同理，labels[batch_indices] 抽取出对应的 10 个标签（1 列）。这行代码配合 yield，实现了每次只“发货”一小批数据给模型训练。
